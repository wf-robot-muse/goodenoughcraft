# VoxelGame

A first-person voxel sandbox game built on **Godot 4.7** with **Voxel Tools**
(Zylann's `godot_voxel` 1.7 GDExtension) — the Minecraft-class stack chosen
for all of Wade's game development, seeded from the `godot-foundation`
project and built/exported entirely by GitHub Actions.

**Phase 1 (current): the playable core.** Streaming blocky terrain with
rolling hills, sandy lowlands, and trees; a walking first-person player
(fly mode included); mine and place blocks from a 9-slot hotbar; a
day/night cycle; and a persistent world that saves your edits.

## Controls

- **Click** the window to capture the mouse
- **WASD** move · **Space** jump · **Shift** sprint
- **Left click** mine · **Right click** place selected block
- **1–9** or **mouse wheel** select block · **F** toggle fly
  (in fly mode: **Space** up, **Ctrl** down)
- **Esc** release the mouse

Creative-style for now: every block type is available in unlimited
quantity. The nine block types — Grass, Dirt, Stone, Cobblestone, Log,
Planks, Leaves, Sand, Brick — are defined in one registry
(`scripts/blocks.gd`); adding a type is a one-line change there.

## The world

- Terrain is generated by a custom `VoxelGeneratorScript`
  (`scripts/terrain_generator.gd`) writing the TYPE channel: grass/dirt/
  stone columns on the hills, sand in the lowlands, sparse trees.
- The world **saves automatically**: block edits go to a Voxel Tools
  region-file stream (`user://world`), and player position, selected
  block, and time of day go to `user://player.json`. Autosave runs every
  30 seconds and on exit; "World saved" flashes on screen.
- To start a fresh world, delete the game's user data folder
  (`VoxelGame` under Godot's `app_userdata` directory for your OS).

## Project layout

- `scripts/blocks.gd` — block registry (ids, names, colors) and library builder
- `scripts/main.gd` — world assembly: environment + day/night, terrain with
  its save stream, player spawn/resume, autosave
- `scripts/player.gd` — first-person controller: walk/jump/fly, mouse look,
  mine/place via `VoxelTool` raycast; hovers at spawn until terrain
  collisions exist so it can never fall through a loading world
- `scripts/hud.gd` — crosshair, controls hint, hotbar
- `scripts/terrain_generator.gd` — the terrain generator described above
- `scripts/smoke_test.gd` — headless CI check: terrain streams, the player
  lands on the terrain, and a block edit round-trips
- `addons/zylann.voxel/` — Voxel Tools 1.7, vendored exactly as released
- `.github/workflows/godot.yml` — CI: import, smoke test, export all platforms

## Building

Pushes to `main` run the workflow: it downloads Godot 4.7.2 and the export
templates, imports the project, runs the smoke test, and exports
**Windows, Linux, macOS, and a debug Android APK** as artifacts named
`voxel-game-windows`, `voxel-game-linux`, `voxel-game-macos`,
`voxel-game-android`. Release builds are attached to GitHub Releases.

Notes inherited from the foundation:

- The Android debug APK packs the addon's editor-variant voxel libraries
  (the addon ships no `template_debug` libraries); a signed release APK
  needs an upload keystore in GitHub Secrets and `--export-release`.
- Builds are unsigned: Windows SmartScreen and macOS Gatekeeper will warn
  on first run until code signing is set up.
